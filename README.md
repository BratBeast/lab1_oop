# Лабораторна робота №1 — Побутові електроприлади

**Варіант 3** · Java 17 · Maven · JUnit 5 · Mockito · JaCoCo

**Репозиторій:** https://github.com/BratBeast/lab1_oop

## Завдання

Створити ієрархію побутових електроприладів, підключити частину з них до розетки, визначити загальну споживану потужність, відсортувати прилади за потужністю та знайти прилади в заданому діапазоні параметрів.

У програмі використовуються інкапсуляція, успадкування та поліморфізм. Для прикладу створено чайники, телевізори й пральну машину.

## Як запустити

Потрібен **JDK 17**. Проєкт використовує **Maven**.

1. Завантажити проєкт із GitHub:

   ```bash
   git clone https://github.com/BratBeast/lab1_oop.git
   ```

2. Відкрити папку `lab1_oop` в **IntelliJ IDEA** як Maven-проєкт (через `pom.xml`).
3. У налаштуваннях проєкту вибрати **JDK 17**, а в **Settings → Build Tools → Maven → Runner → JRE** також вибрати JDK 17.
4. Запустити клас `src/main/java/ua/edu/lab1/app/Main.java`.

Для запуску перевірок у IntelliJ: **Maven → Lifecycle → clean**, потім **verify**.

Якщо Maven установлений і доступний у терміналі, можна виконати:

```bash
mvn clean verify
java -Dfile.encoding=UTF-8 -jar target/household-appliances-1.0.0.jar
```

Якщо в терміналі Windows команда `mvn` не розпізнається, достатньо використати вбудований Maven в IntelliJ IDEA. Для правильного відображення українського тексту в консолі Windows можна виконати `chcp 65001`.

## Структура проєкту

| Клас | Призначення |
| --- | --- |
| `Appliance` | Базові поля, стан і методи електроприладів |
| `Kettle` | Чайник з об'ємом у мілілітрах |
| `Television` | Телевізор з діагоналлю в дюймах |
| `WashingMachine` | Пральна машина з обмеженням завантаження |
| `Apartment` | Список приладів, підрахунок потужності, сортування й пошук |
| `Main` | Демонстрація роботи програми в консолі |

Моделі розміщені в пакеті `model`, логіка квартири — у `service`, точка входу — у `app`.

## Як працює програма

Підключення до розетки та ввімкнення виконуються окремо:

```java
kettle.plugIn();
kettle.switchOn();
```

Увімкнути від'єднаний прилад не можна. Після `unplug()` прилад вимикається. Працюючий прилад споживає номінальну потужність, решта — **0 Вт**. Режим очікування та додаткові режими роботи не враховуються.

Сортування і пошук виконуються за **номінальною потужністю**; межі пошуку включно. Значення приладів у `Main.run()` — демонстраційні.

Приклад результату:

- Початкова споживана потужність: **2120 Вт**.
- Пошук у межах **1000–2100 Вт** знаходить два чайники.
- Після від'єднання чайника Philips: **120 Вт**.

## Тести та перевірка

Використовуються **JUnit 5** і **Mockito**. Тести перевіряють стани приладів, обчислення потужності, сортування та пошук. Mockito застосовано в `ApartmentTest`. Конфігурація `mock-maker-subclass` дозволяє не використовувати динамічне підключення Java-агента.

Перевірка командою `mvn clean verify` на **JDK 17** (12.10.2026):

- **38 тестів пройдено**; `Failures: 0`, `Errors: 0`, `Skipped: 0`.
- **BUILD SUCCESS**.
- **JaCoCo: All coverage checks have been met**.

Після виконання `verify` локальний HTML-звіт JaCoCo доступний за шляхом `target/site/jacoco/index.html`. Папка `target` генерується під час збірки й не додається в Git.
