# Лабораторна робота 1

Варіант 3. Побутові електроприлади.

Програма створює список приладів квартири, вмикає частину з них,
рахує споживану потужність, сортує за потужністю та шукає прилади
в заданому діапазоні.

## Запуск

Потрібна Java 17. В IntelliJ IDEA відкрити папку проєкту,
дочекатися завантаження Maven-залежностей і запустити `Main.java`.

Через термінал із Maven:

```bash
mvn clean verify
java -Dfile.encoding=UTF-8 -jar target/household-appliances-1.0.0.jar
```

Після зміни коду потрібно знову зібрати проєкт і запускати JAR із `target`.
Якщо Windows неправильно показує українські літери, виконати `chcp 65001`.

## Класи

| Клас | Призначення |
| --- | --- |
| `Appliance` | Спільні поля та методи електроприладів |
| `Kettle` | Чайник з об'ємом у мілілітрах |
| `Television` | Телевізор з діагоналлю в дюймах |
| `WashingMachine` | Пральна машина з обмеженням завантаження |
| `Apartment` | Список приладів, підрахунок, сортування і пошук |
| `Main` | Приклад використання та виведення в консоль |

Прилади знаходяться в пакеті `model`, клас квартири - у `service`,
точка входу - в `app`.

## Логіка роботи

Підключення до розетки та ввімкнення виконуються окремо:

```java
kettle.plugIn();
kettle.switchOn();
```

Увімкнути від'єднаний прилад не можна. Після `unplug()` прилад вимикається.
Працюючий прилад споживає номінальну потужність, решта - 0 Вт.
Режим очікування та різні режими роботи в цій моделі не враховуються.

Сортування виконується за зростанням номінальної потужності.
Пошук також використовує номінальну потужність, включаючи обидві межі.
Значення для демонстрації задані в `Main.run()`; це умовні характеристики.

У прикладі чайник і телевізор разом споживають **2120 Вт**.
Пошук від 1000 до 2100 Вт знаходить два чайники.
Після від'єднання чайника Philips залишається **120 Вт**.

Пояснення коду: [docs/explanation.md](docs/explanation.md).
Повний приклад виведення: [docs/sample-output.txt](docs/sample-output.txt).

## Тести

JUnit 5 перевіряє прилади, їхні стани, підрахунок, сортування та пошук.
Mockito використано в `ApartmentTest` для перевірки підрахунку потужності
на підставних об'єктах. Налаштування `mock-maker-subclass` потрібне
для роботи Mockito без динамічного підключення Java-агента.

```bash
mvn test
```

`mvn clean verify` також перевіряє покриття коду через JaCoCo.
Після збірки звіт доступний у `target/site/jacoco/index.html`.
Для актуального звіту виконайте `mvn clean verify`.
Результати: [docs/verification.md](docs/verification.md).
